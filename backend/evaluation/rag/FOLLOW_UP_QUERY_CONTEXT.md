# 追问上下文补全案例集 v1

`follow_up_query_context_v1.json` 是用于评估多轮追问检索的独立案例集，不导入现有单轮评估数据库，也不改变默认功能开关。

## 用例构成

- 17 条 `follow_up`：包含代词指代、主题省略、承接问法、两个相似实体消歧、数字/版本号以及 SQL 片段。
- 4 条 `standalone_control`：覆盖无历史和有历史但问题完整的情况，预期都不调用追问改写模型。
- 每条案例的 `targetCaseId` 指向 `tabkeep_mysql_notes_v2.json` 中已核对的用例；评估时沿用该用例的相关段落和副本金标。
- `referenceQuery` 是人工语义参考，允许模型使用不同措辞；重点检查实体、数字、版本、SQL 片段和问题意图是否保留。

## A/B 使用方法

每条案例都用同一索引、搜索模式、Top K、reranker 和模型配置分别跑关闭/开启两组。将 `history` 按顺序写入同一个临时会话，再提交 `question`；关闭组和开启组使用独立会话 ID，避免互相污染。关闭组保持追问上下文开关为 `false`，开启组只在评估进程中设为 `true`。

记录目标段落的最高排名、Hit@10、MRR、改写调用次数和延迟。`standalone_control` 应保持零次追问改写调用。先报告 17 条追问子集，再单独检查 4 条控制题；不要用整库单轮评估分数替代追问结果。

当前评估工作台和评估 API 是单轮输入，不能直接读取这里的 `history`；本文件先固定案例与金标，需由专门的多轮评估脚本或手动会话流程执行。案例集本身不表示效果已经提升。
