# 视频话题评论采集实施计划

**目标：** 在资讯话题搜索中加入抖音、B站、快手视频搜索，并在搜索后以内存后台任务采集每个视频最多 10 条一级评论。

**架构：** 保持现有 `/news/topic-search` 作为结果入口；新增短期内存评论任务及受新闻访问 Token 保护的轮询接口。视频平台适配与通用任务状态分开，复用当前话题搜索浏览器及用户明确启用的现有 Edge/Chrome 授权会话；评论只进入本次响应和页面状态，不写入资讯数据库。

**技术栈：** FastAPI、Pydantic、asyncio、Playwright、React、TypeScript。

## 任务 1：定义视频搜索和评论任务合约

**涉及文件：** `backend/schemas/news.py`、`backend/services/news/video_comment_jobs.py`

1. 将 `douyin`、`bilibili`、`kuaishou` 纳入话题搜索 provider Literal，并允许请求选择最多 8 个来源。
2. 为视频搜索结果增加稳定的视频标识（沿用 `TopicSearchItem.key`）、平台评论任务标识及评论采集状态合约；评论项只包含平台、作者、文本、时间和原评论链接等展示字段。
3. 新增进程内任务管理器：创建任务时只接受本次搜索返回的视频条目；状态包含 `queued/running/completed/partial/failed/expired`、按平台状态、按视频评论与错误说明、创建和过期时间。
4. 评论上限固定为每视频 10 条一级评论；任务最多保留 20 个，完成后 30 分钟过期，运行任务不因轮询结束而取消。清理过期任务和已结束后台任务，后端关闭时取消并等待全部评论任务。
5. 单条评论任务仅保存最小显示字段；不得存储 Cookie、账号令牌或整页正文。任务快照不写数据库。

## 任务 2：实现三个视频平台搜索与一级评论适配

**涉及文件：** `backend/services/news/video_topic_search.py`

1. 为抖音、B站、快手分别实现关键词视频搜索，统一返回现有话题条目字段 `key/provider/providerTitle/title/author/publishedAt/content/imageUrl/url`；校验结果链接的协议和平台主机名。
2. 为每个平台实现从单条视频页面读取最多 10 条一级评论的适配器。优先读取平台正常页面已加载的内容及平台公开接口响应，不尝试计算或伪造绕过验证码、访问限制所需的签名/令牌。
3. 适配器接受显式的匿名或授权 Playwright context；授权模式只能由调用方在用户偏好开启且会话已连接时提供。匿名和授权路径都按平台隔离，错误转换为不含凭据/评论正文的短错误说明。
4. 对单个平台的视频处理设置并发上限 2、视频间隔至少 1 秒、页面导航和评论读取各自设置有界超时；一个视频失败不停止同平台其他视频，平台限流或挑战出现时停止该平台后续评论请求并保留已有评论。

## 任务 3：接入话题搜索、会话授权和任务查询接口

**涉及文件：** `backend/services/news/topic_search.py`、`backend/services/storage.py`、`backend/routers/news.py`、`backend/main.py`

1. 将三个平台加入 provider 标题、搜索分页游标、结果 host/path 校验和状态报告；视频搜索错误继续隔离在对应平台状态。
2. 扩展账号授权允许列表和默认关闭的授权搜索偏好。新平台授权使用已启用远程调试的本机 Edge/Chrome 新标签；用户自行登录或完成验证，服务端只检查平台登录状态 Cookie 的存在，不读取、传回或记录 Cookie 值。
3. 将视频搜索条目交给任务管理器异步采集评论；`/news/topic-search` 不等待评论任务完成，在响应中返回 `commentTaskId`。只为本次搜索页返回的视频启动任务，翻页搜索有独立任务。
4. 新增 `GET /news/topic-search/comments/{task_id}`，校验本地新闻访问权限并返回任务快照；未知或过期任务返回明确的 404/410。所有任务端点设置 `Cache-Control: no-store`。
5. 在现有应用 lifespan 关闭路径中取消任务并关闭浏览器资源；不得新增数据库迁移或后台订阅采集。

## 任务 4：扩展前端类型、轮询和评论展示

**涉及文件：** `desktop/news-reader/src/api.ts`、`desktop/news-reader/src/TopicSearchPanel.tsx`、`desktop/news-reader/src/styles.css`

1. 同步新增 provider、评论、评论任务和查询 API 的类型定义。
2. 将抖音、B站、快手加入话题搜索选择器和授权账号列表；授权帮助说明用户需要在当前 Edge/Chrome 新标签完成登录/验证，默认仍匿名搜索。
3. 搜索返回后按 `commentTaskId` 轮询任务接口；任务结束、组件卸载或请求编号变化后停止轮询。轮询期间不覆盖搜索结果或触发重复搜索。
4. 在视频卡片中显示评论采集状态和数量，并用可展开区域展示最多 10 条一级评论；失败只显示后端提供的安全短说明。非视频内容不显示评论区。
5. 更新隐私说明，指出视频评论只保存在当前后端进程的短期内存和当前页面状态，不进入订阅、资讯库或搜索历史。

## 集成审查与验证边界

- 逐项核对后端 schema、provider 搜索状态、偏好、授权端点、任务轮询 API、前端类型和选择器中的 provider ID 完全一致。
- 静态检查请求/响应字段命名、超时与取消路径、任务过期清理、Cookie 和评论文本日志边界，以及是否存在将评论写入资讯存储的调用。
- 不新增或运行自动化测试；不启动后端。实现后只报告实际完成的静态检查，不将未运行的构建或手动行为描述为已通过。

## 明确不在本次范围

- 不采集二级评论，不订阅评论，不定期刷新评论，不将评论或任务写入数据库。
- 不复制 MediaCrawler 源码，不绕过验证码、风控或登录限制；平台拒绝访问时保留平台级/视频级状态。
