# 发现与决策

## 用户需求

- 先验证现有关键词推荐，再对照语义及混合排序。
- 推荐只排序已采集资讯；“最新”维持时间顺序。
- 本机抽 30 篇人工标注，不将标签混入兴趣事件、不提交资讯文本；用户后续明确要求为它加开发专用交互页。
- 语义评估只在用户显式调用时使用现有配置的 embedding 服务；不发送原始浏览器历史或 URL。
- 只有评估达到计划门槛才考虑接入；正式资讯 UI 不展示评估功能，也不引入 K-means。

## 初始仓库状态

- 当前分支 `master`，工作区已有大量未提交改动，需保留并检查相关改动；不回滚或提交。
- 兴趣推荐当前算法版本为 `local-keywords-v5`。
- 推荐计算正文优先关键词匹配，标题仅补分；来源偏好与新鲜度各自有上限，首页前段做来源多样性调整。
- 当前已有反馈/推荐理由测试；存在 embedding 配置与复用的 `services.knowledge.embeddings.embed_texts`。
- 尚未发现新闻推荐的独立 embedding 缓存或语义排序实现。

## 关键词推荐基线（`local-keywords-v5`）

| 部分 | 当前规则 |
|---|---|
| 行为强度 | 内容画像权重：点赞 `+3.0`、不感兴趣 `-3.0`、少推类似 `-2.0`、打开原文 `+0.45`、浏览历史 `+0.25`、建议接受 `+2.5`、建议忽略 `-1.0`；曝光 `0`，订阅新增对内容主题 `0` |
| 内容匹配 | 每个主题最多使用 4 个高 IDF 关键词；正文命中是必要条件，词项覆盖分 `0.7 × 正文 + 0.3 × 标题`，再乘 `tanh(|主题分| / 2.5)`。正向分为 `1 - exp(-前 5 个命中主题贡献之和)`；负向项乘 `0.72` 后扣减 |
| 来源偏好 | 来源权重：订阅新增 `+0.25`、打开原文 `+0.45`、浏览历史 `+0.25`、点赞/踩 `±1.1`、少推类似 `-0.85`、建议接受/忽略 `+0.8/-0.4`；反馈只取每篇文章最新赞踩，按 45 天指数衰减，经 `tanh` 缩放，最终限制在 `±0.12` |
| 新鲜度 | 按年龄指数衰减，时间常数 3.5 天，最多加 `+0.12` |
| 来源多样性 | 仅调整全局推荐前 20 条；同来源每重复一次扣 `0.075`，惩罚封顶 `0.24`，不修改基础兴趣分 |
| 最终排序 | 正负内容匹配 + 有界来源分 + 有界新鲜度，再按前段来源重复惩罚重排；最新列表仍为时间序 |

## 后续发现

- 资讯相关测试基线 54 项通过；`FastAPI TestClient` 输出现有 httpx deprecation warning。
- 系统 PATH 中 `python` 是失效 Windows Store alias；项目配置的可用解释器为 `%USERPROFILE%\\.conda\\envs\\tabkeep\\python.exe`。
- `EmbeddingConfig` 使用现有 OpenAI-compatible provider，缺省禁用；可调用 `services.knowledge.embeddings.embed_texts`。
- `news.sqlite3` 位于运行时 `storage.DATA_DIR`，评估文件也应写到同目录下的隔离子目录，不写入仓库。
- 新增开发专用评估脚本：`prepare` 抽取“当前推荐 / 最新未推荐 / 按来源均衡随机”候选；`label` 在终端盲标；`evaluate` 才会调用 provider。
- 标注 manifest 只保存资讯 ID、内容指纹、算法/画像快照与标签；不保存正文、标题、URL或完整浏览记录。
- 本地向量缓存按 provider/model 摘要和正文摘要键控，不保存 API Key 或正文；API 错误不会改变线上推荐。
- 语义原型按现有多个正负画像主题计算最高余弦匹配；混合方式按固定 0.5 组合关键词与语义内容分，再共用来源、新鲜度和多样性排序。
- 资讯专项测试现为 63 项通过；新增覆盖抽样去重、标签隔离、embedding 输入清理、缓存、正负兴趣分离、排序指标与 provider 未配置路径。
- 资讯专项测试 63 项、后端全量测试 187 项通过；新增 provider 失败隔离验证，失败时不生成比较报告，线上关键词推荐排序保持不变。
- “近期未入选”样本现在只从关键词基线未排序的文章中抽取；随机组按来源均衡补足，避免把已在推荐排名中的条目误标为未入选。
- 未调用实际 embedding 服务，也未对本机真实资讯生成人工标签；NDCG@10 对比结论需在用户完成标注后才会产生。
- 新增开发专用多页面入口 `dev-recommendation-evaluation.html` 和逐篇标注页；支持新建/恢复批次、即时保存兴趣标签、显示进度、显式调用 embedding 对比及查看指标/前三种排序前 10 条。

### 决策

- **正式推荐已切换为 RRF 主方案**；50:50 分数混合保留为评估对照，关键词排序继续作为回退和基线。
- 选择依据是 RRF 按 `sum(1 / (60 + rank))` 融合两份榜单的名次，不依赖语义分数与关键词分数处于同一尺度；本批次覆盖全部确定标签，整批 NDCG 接近语义排序和混合排序。该批次中混合排序的 AP、AUC 更高，语义排序的 NDCG 略高，因此这不是“RRF 在所有指标上胜出”的结论，而是用户决定先将 RRF 用作正式主方案。
- 接入实现沿用评估时的 `sum(1 / (60 + rank))`：正式推荐分别计算关键词榜和正文语义榜，再融合榜单名次。语义输入是去 URL/HTML 后的文章正文（最多 5,000 字符）与画像主题标签/关键词（最多 300 字符）；仅在用户打开推荐视图且 embedding 已配置时请求该服务。向量复用本地缓存，缓存未命中最多每批 24 条。
- embedding 未启用、返回错误或向量无效时，正式推荐回退到关键词排序，并将 `recommendationState` 设为 `keyword_fallback`；资讯页继续可用且显示回退提示。语义请求日志只记录异常类型，不记录文章文本或 provider 返回的错误正文。最新列表不调用 embedding。
- 按用户要求，暂不继续算法验证：不创建新评估批次，也不实际请求 embedding 服务。此次只完成正式 RRF 接入与模拟测试；100 篇结果仍是阶段性依据，单用户、单批次不足以证明普遍效果。后续若恢复验证，继续使用整批 NDCG、AP、Pairwise AUC、覆盖率和随机基线，并覆盖不同主题与来源。
