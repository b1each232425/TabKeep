# 兴趣画像与话题推荐决策

日期：2026-10-16

## 决策

- 当前不把 K-means 纳入兴趣计算或推荐核心链路，也不让候选话题生成依赖聚类结果。
- 推荐以本地软兴趣画像为依据：将浏览、阅读、订阅和反馈事件按行为权重与时间衰减聚合，再使用平台话题目录的分类、标签或关键词为候选打分。
- 候选评分基于聚合后的画像，不逐条将浏览历史与每个候选话题配对。新增候选仍可直接参与评分，不受既有聚类边界限制。
- K-means 只作为未来可选的兴趣地图展示或探索实验。若实现，应评估聚类是否提升可解释性，并避免高频页面压制小众兴趣；推荐仍保留画像中的软权重。

## 原因

K-means 可以把历史内容归组，帮助展示一段时间内的兴趣主题，但硬聚类不擅长表达重叠或新出现的兴趣，也不能单独解决候选话题推荐。对当前规模的候选目录，先聚合事件再按目录元数据评分更直接，也避免引入向量化和聚类维护成本。

Chrome History Explorer 的 Interest Map 可作为历史兴趣可视化参考，不作为 TabKeep 推荐流程的前置算法。

## 对数据设计的影响

- 保留原始兴趣事件和可重建的加权画像作为事实来源。
- 核心画像不要求固定的 `cluster_id` 或聚类成员关系。
- 将来若增加聚类，作为可重建的派生视图保存，不改变现有画像与推荐接口的基本语义。
