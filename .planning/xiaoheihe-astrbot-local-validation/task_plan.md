# AstrBot 小黑盒扫码登录本机验证

## 目标

在隔离目录中克隆并启动 AstrBot 及其小黑盒插件，验证 AstrBot 是否能从小黑盒接口拿到有效二维码，用于与 TabKeep 当前实现对比。

## 阶段

- [complete] 检查 AstrBot 与插件的启动方式、依赖及端口要求
- [complete] 在独立临时目录获取源码并准备本机运行环境
- [complete] 限定本机监听地址后启动 AstrBot，确认管理页与插件可用
- [complete] 触发二维码请求，记录脱敏结果并清理启动进程
- [complete] 汇总成功/失败证据、请求差异和后续修复方向

## 安全边界

- 不读取、复制或导入用户现有小黑盒 Cookie、Token、浏览器会话或账号配置。
- 不输入账号密码、扫码授权或凭据；只验证服务是否返回二维码内容。
- AstrBot 与插件源码、运行环境放在工作区内独立临时目录，不改 TabKeep 产品代码。
- 服务仅绑定 `127.0.0.1`，测试结束后停止由本任务启动的进程。
- 不构建或重新打包 TabKeep。

## 错误记录

| 错误 | 尝试 | 处理 |
| --- | --- | --- |
| 系统 `python.exe` 指向 Windows Store 别名且不可启动 | 初次 Python 探测 | 探测 `uv`、Conda/其他解释器；必要时改用可用运行时或在可复现阻塞时停止 |
| 系统默认 Python/py 启动器不可用 | `python -` 与 `py -0p` | 找到已安装的 Conda 发行版，后续为验证新建工作区内独立环境 |
| Conda 默认包缓存目录不可写 | 在 workspace 路径创建独立 Conda 环境 | 改为使用本机现有解释器创建 workspace 内 venv，避免改 Conda 包缓存或现有环境 |
| pip 使用镜像源时安装超过 90 秒无进度 | pip install 全量 requirements | 取消后改用 uv 同一索引安装；依赖解析与安装成功 |
